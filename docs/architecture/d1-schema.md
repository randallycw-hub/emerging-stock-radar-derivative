# D1 Schema Contract

The forward-only `0004_listing_application_completeness.sql` migration adds `chairman_name` to `listing_applications`, preserving the `NormalizedListingApplicationWithStage11586.chairmanName` field. Listing chronology is stored only as validated monotonic ISO dates from application through listing. A normalized unavailable `applicationCapitalThousandsTwd` value (`""`) is stored as SQL `NULL` and restored as `""` on reads.

This offline schema is SQLite-compatible and is intended for a future Cloudflare D1 repository. It stores only metadata and normalized records; raw HTTP payloads, fixtures, adapters, orchestration, APIs, bindings and deployment are out of scope. Every record is linked to an immutable `source_snapshots` row. Dataset-specific tables use text identifiers, non-negative count checks, explicit enum checks, foreign keys, natural-identity uniqueness and query indexes. No market quote, volume, arbitrage, recommendation or generic JSON record table is present. Migrations are additive (`0001_pipeline_core.sql` through `0005_bond_contract_completeness.sql`) and contain no destructive or seed statements. The forward-only profile migration persists `paidInCapital`, `chairperson`, and `generalManager`. The forward-only bond migration adds `source_bond_type_code`, `series_number`, `tranche_number`, and `security_description`; together these migrations complete the 28567 and 11406 normalized contracts without rewriting historical migrations. D1 is not created or bound in Task I.

## Repository mapping and read boundary

The repository has four dataset mappings, each with fixed parameterized SQL and an explicit row-to-domain mapping: `94025` reads and writes `emerging_monthly_revenue`; `28567` uses `public_company_profiles`; `11406` uses `bond_issuances` with `bond_put_rights`; and `11586` uses `listing_applications` with `listing_application_underwriters`. Every dataset read is scoped to its snapshot, source, and resource. Both child collections are joined through their selected source/resource-scoped parents and ordered deterministically by parent identity and `sequence`.

Bond put-right rows preserve the parent source-record identity and must have contiguous one-based sequences, unique strictly ordered ISO dates within the bond lifecycle, and one shared positive normalized decimal price. Unexpected row shapes, orphan children, sequence gaps, duplicate dates, mismatched source/resource/snapshot identities, invalid chronology, unsupported dataset values, and incomplete write results fail closed: no partial record is returned or persisted. Every dataset parent or child query also requires explicit D1 `success: true` and an actual `results` array; failed or evidence-free reads throw `RepositoryError("DATASET_RECORD_READ_FAILED")` rather than being treated as empty data. A published-pointer read selects only the requested `dataset_id`, maps the allowed pointer fields explicitly, and returns `undefined` for no row, a mismatched dataset, or an invalid row shape.

D1 reads are local database operations only. They never fetch, contact, substitute, or otherwise consult an external source.
