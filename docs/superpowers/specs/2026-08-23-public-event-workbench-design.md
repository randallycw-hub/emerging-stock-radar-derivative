# 公開事件工作台改版設計

## 目的與範圍

本改版以 CyclesInvest 的「可組合資料工作台」和「公司跨資料關聯」為參考，但不複製其交易排行、評分、即時行情或未標示資料來源的內容。

第一階段調整三個既有靜態展示頁面：首頁、可轉債、IPO 時程。目標是讓使用者先看見近期公開事件，再能快速進入資料表、單檔明細和原始公告。既有興櫃頁不改變其資料範圍，只為後續公司關聯保留一致的 issuer code。

本改版不新增會員、付費、推播、選股分數、買賣／避險指示、目標價、預測或盤中／延遲報價。TCRI 不納入正式資料，除非未來取得明確授權。

## 使用者流程

```text
首頁的近期事件
  ├─ 近期發行／掛牌 ──> IPO 時程（該公司、最近事件、完整時間線）
  ├─ 90 日內權利事件 ─> 可轉債清單（已套用事件條件）
  ├─ 一年內到期 ─────> 可轉債清單（已套用到期條件）
  └─ 資料待補 ───────> 可轉債清單（已套用資料品質條件）

可轉債清單 ──> 單檔明細（狀態矩陣、歷史、條款、官方證據）
IPO 時程 ───> 展開完整事件、承銷資訊與官方證據
```

所有連結保留 URL 狀態，使篩選、排序、搜尋和展開的內容可分享及重新載入。

## 資訊架構與版面

### 首頁：雜誌式入口加上事件列

保留既有四個主入口與暖白紙本風格。標題下方增加精簡的事件列，僅顯示：近期發行／掛牌、90 日內權利事件、一年內到期、資料待補。每個項目顯示筆數、最接近事件日期和資料日期；點選後帶入目標頁的中性篩選條件。

首頁不顯示排行榜、漲跌幅、推薦字眼或過多表格。更新區一律同時顯示整份摘要的資料日期及來源覆蓋狀態。

### 可轉債頁：資料工作台

頁首由標題、資料日期、來源摘要和四個事件捷徑組成。桌面版將篩選區固定在表格上方，依序為：

1. 搜尋代碼／債券名稱／發行人。
2. 近期發行／掛牌、90 日內權利事件、一年內到期、資料待補四個快捷條件。
3. 進階條件：發行日、到期日、流通餘額比例、擔保狀態、資料品質。每個條件都可合併，缺值在啟用該條件時排除。
4. 可分享的排序與分頁狀態。

主表固定顯示：CB 代碼／名稱、發行人、流通餘額比例、下一事件、到期日、資料日期、資料品質。其他已驗證的盤後衍生值只放於可選欄位或單檔內容，不讓寬表成為閱讀障礙。小螢幕維持一列一張精簡卡片，讓代碼、下一事件、到期日、資料品質優先顯示。

單檔頁最上方新增「目前資料快照」：資料日期、流通餘額、與前期可比較時的變動、下一事件、到期日。下方沿用現有狀態矩陣、條款、歷史圖表與證據區塊。若某一資料沒有經核准的公開來源，顯示「目前無核准公開資料／待確認」及欄位層級原因，不以推測值代替。

### IPO 時程：事件生命週期

延續既有列表／月檢視、篩選、排序和單列完整歷程。列表優先以最近公開事件排序，並強化每列的：公司／市場、目前階段、最近事件與距今天數、下一已知事件、定價狀態、掛牌日、資料來源與資料日期。

展開內容使用固定事件順序：公告、送件、核准／生效、詢圈或競拍、轉換價確認、掛牌。未公布的節點顯示「尚無公開資料」，不可顯示成已完成。承銷商、發行量與競拍結果僅在已驗證的官方來源有資料時呈現。

## 資料與來源規則

現有 `bond-market-view`、`11406`、IPO snapshot 與來源登錄表是第一階段唯一正式資料輸入。事件摘要只由已發布的 IPO event、可轉債 `nextEventDate`、到期日和資料品質欄位衍生，不新增第三方抓取。

| 資料類型 | 正式來源與用途 |
|---|---|
| CB 條款、發行與目前餘額、擔保、賣回權 | TPEx 轉（交）換債發行資料及已上／下市資料 |
| CB 權利事件 | TPEx 權利資料與已驗證公告 |
| IPO 事件、競拍與掛牌 | MOPS、TWSE／TPEx 公告與既有官方 event adapter |
| 收盤後可用市場欄位 | 僅既有經人工核准的官方盤後快照 |

每個頁面須標示資料日期；每個可展開的證據項須標示來源名稱與原始連結。財務期間資料與市場資料不得假設同日，未來若加入財務資料，需獨立顯示財務期間截止日、公告日和市場資料日。

## 技術設計

第一階段不改變資料庫 schema 或資料來源授權範圍。靜態展示層新增一個純衍生的 event digest：輸入是既有資料檔，輸出是首頁事件數、最接近日期與對應的目標 URL。資料不存在、日期無效或來源未發布時，該摘要項目顯示明確空狀態且不產生誤導性數字。

預計調整的既有介面：

- `static-showcase/index.html`、`assets/home-page.js`：首頁事件列與資料狀態。
- `static-showcase/bonds.html`、`assets/bonds-page.js`、`assets/bond-detail-page.js`：快捷／進階篩選、快照列與 URL state。
- `static-showcase/ipo.html`、`assets/ipo-page.js`：最近事件優先的欄位與事件生命週期呈現。
- `static-showcase/assets/app.css`：同一套紙本色系下的工作台密度、響應式表格與狀態樣式。
- `static-showcase/data/manifest.json` 和 staging scripts：僅在需要把 event digest 併入正式展示輸出時調整。

第二階段才評估「公司資料頁」：使用 issuer code 串聯興櫃、CB、IPO 與證據。它不屬於第一階段，以避免在未確認跨市場代碼品質前建立錯誤連結。

## 錯誤處理與可近用性

- 資料檔無法載入時，保留頁面結構並顯示不可用原因；不退回 fixture 或舊快照。
- 篩選結果為零時，列出目前條件並提供清除條件操作。
- 所有快捷、排序、展開與分頁控制均可由鍵盤操作，且正確更新 `aria-selected`、`aria-sort` 或展開狀態。
- 日期、來源、缺值狀態不可只以顏色表示；色彩僅作次要輔助。

## 驗收與測試

1. 首頁四個事件捷徑可從既有公開資料正確導到對應頁面及 URL 篩選狀態。
2. 可轉債進階條件可合併；啟用條件時缺值列不會被誤納入；清除後恢復完整清單。
3. 單檔快照不會把不同資料日期混為同一更新日，缺值有明確原因。
4. IPO 每列事件順序正確，未公布事件不會被顯示為已完成；列表與月檢視維持一致結果。
5. 所有新增正式欄位都具有來源與資料日期，且不使用 Yahoo、券商、CBAS、未授權 TCRI 或即時報價。
6. 現有靜態展示、IPO、CB 明細、來源驗證、無即時行情與正式建置測試全部通過；並執行 typecheck、lint、test、build。

## 明確決策

- 採「雜誌式首頁 + 事件工作台」混合版，而非將首頁改成選股排行。
- 資料廣度可逐步接近參考站，但以官方來源、資料日期與可追溯性優先。
- 第一階段只做資料查閱與事件追蹤，不建立推薦、評分或操作邏輯。
