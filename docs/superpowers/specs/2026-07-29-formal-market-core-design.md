# 正式市場核心第一階段設計

**目標：** 建立可在本機完整操作、資料欄位清楚且可驗證的興櫃與可轉債市場核心，並納入 IPO 時程與資料來源資訊。

## 範圍

第一階段不處理 Cloudflare 或其他雲端部署，先完成前端與本機資料流程。GitHub Pages 靜態展示版保留，不與正式資料流程混用。

## 架構

資料模型分為公司、可轉債、IPO 時程與資料來源四類。查詢層提供統一的搜尋、分類、排序、分頁與明細查詢；頁面層提供市場總覽、興櫃清單、可轉債橫式資料表、IPO 時程及公司／債券明細；驗證層確認每個可見數值具有資料日期與來源，並禁止把興櫃收盤價標示成即時行情。

## 使用者流程

1. 使用者進入市場總覽，看到興櫃、可轉債與 IPO 時程的資料摘要。
2. 使用者可用代號、名稱、產業、債券狀態與日期範圍篩選。
3. 可轉債清單以橫式欄位顯示核心條款：代號、名稱、發行日、到期日、票面利率、轉換價格、轉換期間、發行總額、流通餘額、收盤價、轉換價值、溢價率、資料日期與來源。
4. 興櫃清單顯示收盤價、漲跌、成交量、成交金額、日期與來源；不顯示即時行情欄位。
5. 明細頁顯示完整條款、事件時間軸、資料來源與最後更新時間。

## 視覺與可用性

- 深色與淺色主題可切換，使用高對比文字與邊框，不使用低對比綠色文字。
- 桌面寬度優先顯示完整表格；小螢幕提供固定欄位與水平捲動。
- 重要狀態使用文字與圖示同時呈現，不能只依賴顏色。
- 每個資料區塊顯示資料日期與來源連結，讓使用者能判斷資料新鮮度。

## 錯誤與資料規則

- 缺失值顯示「—」並保留欄位，不以 0 代替未知值。
- 日期、價格、利率、金額與百分比使用固定格式化函式。
- 興櫃價格一律標記為「收盤價」；若資料標記為即時，前端拒絕渲染該筆資料。
- API 或本機快照失敗時，顯示可理解的錯誤訊息、最後成功資料日期與重試入口。

## 驗證

- 建置、型別檢查、Lint 與既有測試全部通過。
- 新增頁面契約測試，確認核心欄位、資料日期、來源與收盤價規則。
- 新增主題對比與可見文字測試，避免深色或淺色主題出現低對比文字。

## 非本階段項目

- Cloudflare Worker、D1 遠端資料庫與排程抓取。
- 即時行情串接。
- 使用者帳號、個人化自選與通知。
