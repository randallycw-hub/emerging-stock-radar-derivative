# 興債觀測網正式首頁設計

日期：2026-07-28  
狀態：已核准  
範圍：正式首頁、研究頁資訊層級、完整資料發布門檻與品牌視覺  
不在本規格範圍：部署、遠端 D1 建立、會員、付款、廣告、行情、成交量、投資推薦

## 1. 目標

建立兼顧一般使用者與研究型使用者的正式入口。首頁須簡潔地回答「目前有哪些資料、近期發生什麼事、下一步去哪裡研究」，完整資料則由專屬研究頁承載。

正式首頁不得使用 fixture、樣本或未完成資料。興櫃公司、可轉債、上市櫃進度三類正式資料必須全部完成、通過驗證並發布為同一合格 snapshot 後，首頁才可公開。

## 2. 產品原則

- 正式品牌固定為「興債觀測網」。
- 固定副標題為「興櫃公司、可轉債與上市櫃進度資訊」。
- 首頁簡潔，內頁完整。
- 所有正式資料均可追溯至允許使用的官方來源。
- 不提供即時或延遲股價、成交量、套利資訊、選股訊號或投資推薦。
- 不使用其他券商網站或未授權行情 API。
- 資料不完整時明確顯示狀態，不以零筆、假資料或模糊訊息掩飾。
- `/dev-preview` 與正式路由隔離，維持 `noindex`，不得成為正式資料來源。

## 3. 資訊架構

### 3.1 正式首頁

`/` 是一般使用者入口，由伺服器端讀取單一 published snapshot。首頁包含：

1. 品牌、固定副標題、主要導覽與全站搜尋。
2. 三類資料的資料筆數、官方更新時間與本站擷取時間。
3. 近期上市櫃進度。
4. 可轉債重要日期。
5. 興櫃公司資料異動。
6. 興櫃公司、可轉債、上市櫃進度三個研究入口。
7. 資料來源、資料方法、免責聲明、隱私權政策與防詐提示。

首頁只顯示足以導覽與理解近期重點的摘要，不在首屏放置大型完整資料表。

### 3.2 研究頁

- `/emerging`：興櫃公司清單、搜尋、篩選、排序、分頁與資料狀態。
- `/emerging/[companyId]`：公司基本資料、相關可轉債、上市櫃進度與事件時間軸。
- `/bonds`：可轉債清單、條件、重要日期、搜尋、篩選、排序與分頁。
- `/bonds/[bondId]`：發行條件、重要日期、發行公司、官方來源與更新資訊。
- `/listing-progress`：上市櫃申請進度、事件、搜尋、篩選、排序與分頁。

上述頁面共用 entity ID、事件模型、來源標示、snapshot 版本及一致的搜尋與空狀態語言。

### 3.3 響應式呈現

- 桌機版可使用表格承載完整資料。
- 手機版首頁先呈現摘要與重要事件。
- 手機版完整資料優先使用分段卡片或可理解的逐列內容；只有無法合理折行的資料才使用局部水平捲動。
- 導覽、搜尋、篩選、來源與更新時間須能以鍵盤和觸控操作。

## 4. 首頁元件

### 4.1 頂部導覽

導覽項目為首頁、興櫃公司、可轉債、上市櫃進度及資料來源。搜尋可依公司名稱、公司代號或可轉債識別碼找到正式資料實體。

### 4.2 首屏摘要

首屏顯示三類資料的最新合格狀態。數字必須來自同一 published snapshot。每項摘要連往對應研究頁。

### 4.3 近期重要事件

首頁分三組顯示：

- 上市櫃進度變更。
- 可轉債重要日期。
- 興櫃公司資料異動。

每筆事件至少包含實體名稱、事件類型、有效日期、官方來源名稱與資料日期。首頁筆數受限，完整事件在研究頁查看。

### 4.4 資料與法律資訊

所有正式資料頁須顯示資料提供機關、正式資料集名稱、授權條款、官方資料集連結、官方更新時間、本站擷取時間與「資料經興債觀測網整理」。

網站不得使用使人誤認為官方機關的 Logo、名稱、配色或版式。

## 5. 資料發布架構

採伺服器端聚合首頁。首頁不得直接呼叫外部資料來源，也不得由瀏覽器分別拼接多個不一致版本。

資料流程：

1. 分別擷取興櫃公司、可轉債、上市櫃進度資料。
2. 驗證來源、schema、必要欄位、筆數合理性、自然鍵與跨資料集關聯。
3. 將三類資料寫入同一候選 snapshot。
4. 執行 snapshot 完整發布檢查。
5. 三類皆通過時，以 compare-and-swap 原子切換 published pointer。
6. 首頁與研究頁只讀取 published pointer 指向的 snapshot。

不得因單一資料集成功而發布部分首頁。候選 snapshot 失敗時保留上一個合格 snapshot，不改動 published pointer。

## 6. 正式公開門檻

正式首頁只有在下列條件全部成立時才可公開：

- 興櫃公司資料集存在且通過合約驗證。
- 可轉債資料集存在且通過合約驗證。
- 上市櫃進度資料集存在且通過合約驗證。
- 三類資料屬於同一 snapshot。
- 所有必要來源資訊與時間欄位存在。
- 跨資料集 entity 關聯沒有阻斷性錯誤。
- 沒有被禁止的行情或未授權來源欄位。
- 測試、lint、typecheck、build 與視覺檢查通過。

在門檻達成前，只能使用本機或受限開發預覽，不部署正式首頁。

## 7. 狀態與錯誤處理

- **尚無合格 snapshot**：顯示資料建置中及資料標準說明，不顯示零筆或 fixture。
- **更新失敗但有舊 snapshot**：繼續提供上一個合格 snapshot，標示其資料日期、擷取時間與更新狀態。
- **實體不存在**：明確顯示找不到指定公司或可轉債。
- **本版未收錄**：說明目前 published snapshot 未包含該實體。
- **服務暫不可用**：提供可重試狀態，不把技術錯誤或堆疊資訊暴露給使用者。
- **來源狀態異常**：保留來源健康資訊供維運判斷，不將未驗證候選資料發布給使用者。

## 8. 視覺方向

### 8.1 色彩

採用「Cloud Dancer × Transformative Teal」方向：

- Cloud Dancer 類霧白作為主要閱讀底色。
- Transformative Teal 類深海藍綠作為品牌主色、主要互動與導覽定位。
- 冷灰用於結構線、次要文字和表格分隔。
- 狀態色僅用於具有語意的成功、警示與錯誤。
- 正式實作時須建立具體 design tokens，並以 WCAG 對比測試決定最終螢幕色值；趨勢色名稱只作方向，不直接視為可存取色值。

參考：

- Pantone 2026 Color of the Year：Cloud Dancer。
- WGSN／Coloro 2026 Colour of the Year：Transformative Teal。

### 8.2 反 AI 同質化規則

- 不使用紫藍霓虹漸層作為品牌主視覺。
- 不使用玻璃擬態、漂浮發光卡片或大面積模糊光暈。
- 不使用過度圓角、膠囊化所有控制項或裝飾性 3D 插圖。
- 不以大量不同顏色區分同層級卡片。
- 以財經出版物與研究終端的資訊秩序為核心：清楚的基線、穩定欄寬、克制留白、精準數字與少量品牌色。
- 品牌辨識來自字體層級、網格、線條、資訊編排與固定主色，不依賴短期特效。

## 9. 可存取性與內容品質

- 主要文字、互動控制、圖示和狀態須符合 WCAG AA 對比要求。
- 所有互動元件具可見焦點、可讀標籤與合理的鍵盤順序。
- 不以顏色單獨傳達狀態。
- 日期、數字、來源與更新狀態使用一致格式。
- 空狀態、錯誤狀態與建置中狀態使用不同且明確的文字。
- 頁面 metadata、標題結構、canonical 與 sitemap 對應正式資訊架構。

## 10. 驗證策略

### 10.1 資料與發布

- Repository contract tests。
- 三類資料 schema 與必要欄位測試。
- 跨資料集關聯與 entity ID 測試。
- 同一 snapshot 隔離測試。
- published pointer compare-and-swap 測試。
- 部分成功不得發布的測試。
- 舊 snapshot 保留與回退行為測試。
- 禁止來源及禁止行情欄位掃描。

### 10.2 網頁

- 首頁有／無合格 snapshot 的伺服器端呈現測試。
- 三類摘要與研究入口連結測試。
- 搜尋、篩選、排序、分頁與詳情頁測試。
- 不存在、未收錄、過期及暫不可用狀態測試。
- 桌機與手機視覺檢查。
- 鍵盤操作、焦點、語意結構與色彩對比檢查。
- `npm test`、`npm run lint`、`npm run typecheck`、`npm run build` 與 `git diff --check`。
