# 興債觀測網多分頁與興櫃盤後市場設計規格

日期：2026-07-30  
狀態：待使用者最終確認

## 目標

將目前以錨點向下捲動的單頁網站，改為五個主要分頁，降低長表格造成的操作負擔，並將首頁主標題改為「可轉債與興櫃盤後資訊」。

興櫃市場頁參考使用者提供的市場雷達資訊層級，但不複製其資料、不使用其即時行情端點，也不呈現盤中成交價、買價或賣價。興櫃價格一律採用櫃買中心盤後資料的專業名稱「當日成交均價（盤後）」。

## 主要分頁

### 1. 首頁 `index.html`

- 主標題：「可轉債與興櫃盤後資訊」
- 顯示最近盤後資料日。
- 顯示可轉債檔數、具有可驗證估值的檔數、興櫃公司檔數及近期 IPO 時程數。
- 以四個入口卡片連結至可轉債、興櫃市場、IPO 時程及資料方法。
- 首頁不再承載完整長表格。

### 2. 可轉債 `bonds.html`

- 保留現有完整可轉債總表與篩選功能。
- 保留 CB 收盤價、標的股收盤價、目前轉換價、轉換價值、溢價率、成交量、流通餘額及到期／賣回事件。
- 點選可轉債後，使用 `bonds.html?bond=<代碼>` 進入同一頁面的詳細模式；詳細模式取代總表內容，不把詳細資料接在長表格下方。
- 詳細模式包含價格日期、估值日、價格走勢、轉換與餘額、契約生命週期、發行條款、公告文件及資料來源。
- 提供明確的「返回可轉債總表」按鈕。

### 3. 興櫃市場 `emerging.html`

版面採三層資訊結構：

1. 盤後摘要
   - 興櫃公司家數
   - 有效成交樣本數
   - 上漲／下跌／平盤家數
   - 當日成交總金額
   - 資料日期
2. 市場排行
   - 單日漲幅
   - 單日跌幅
   - 成交量
   - 成交金額
   - 排行僅使用同一盤後資料日的有效數值。
3. 完整市場表格
   - 代號／公司
   - 產業
   - 當日成交均價（盤後）
   - 前一交易日均價
   - 單日漲跌額
   - 單日漲跌幅
   - 成交量
   - 成交金額
   - 資料日期

篩選功能包含公司代號／名稱搜尋、產業、漲跌狀態、成交量門檻與排序。桌面版使用橫式表格並預設每頁 50 筆；手機版使用摘要卡片並預設每頁 25 筆，不要求使用者左右移動才能看見主要欄位。

原有興櫃月營收資料保留，透過同頁的「盤後行情／營運資訊」次導覽切換；兩者不在同一畫面混排，避免把不同資料年月誤認為同一行情日。

### 4. IPO 時程 `ipo.html`

- 保留申請、審議、競拍、承銷及掛牌日期。
- 提供公司搜尋、目前階段及年份篩選。
- 以近期事件優先排序，歷史資料可切換查看。
- 不顯示未經來源核准的承銷價或即時市場價格。

### 5. 資料方法 `methodology.html`

英文眉題改為 `DATA METHODOLOGY`，中文主標題改為「資料來源與計算方法」。

四個主要說明項目改為：

- 「可轉債發行條款」：證券櫃檯買賣中心可轉債發行資料。
- 「盤後行情資料」：臺灣證券交易所與證券櫃檯買賣中心盤後資料。
- 「轉換價格資料」：公開資訊觀測站發行資料。
- 「估值計算原則」：僅採相同交易日之可轉債與標的股價格計算轉換價值及溢價率；日期不一致時不進行推算。

另增加興櫃欄位定義，明確說明興櫃沒有一般上市櫃股票的收盤價，網站所稱盤後價格為「當日成交均價」。

## 全站導覽

- 桌面版使用固定側邊導覽；每個選項連向獨立 HTML 頁面，不使用頁內錨點當作主要導覽。
- 手機版改為頂部可橫向滑動的精簡導覽列，內容區本身不因導覽而產生左右捲動。
- 每頁顯示目前所在分頁。
- 深淺色設定沿用同一個 `localStorage` 鍵值，跨頁保持一致。
- 所有頁面使用相同品牌抬頭、資料日期、免責聲明及頁尾。

## 資料來源與正確性

- 參考網站只作為資訊層級與互動方式的參考，不作為資料來源。
- 興櫃盤後市場候選來源為櫃買中心 OpenAPI `tpex_esb_latest_statistics`。
- 實作前必須完成候選來源的欄位、日期、缺值、無成交與重複代號驗證，並將核准結果加入現有 Source Registry。
- 若來源欄位與預期語意不一致，該欄位不得發布，也不得以第三方行情或推算值補上。
- 漲跌額與漲跌幅只有在當日成交均價與前一交易日均價皆存在時才計算。
- 成交量、成交金額與價格保留各自的來源單位，顯示格式化不得改變原始數值。
- 每個資料檔保留資料日、擷取時間、來源網址、筆數與 SHA-256 雜湊。

## 前端結構

- 共用版型、導覽、主題切換及格式化器拆為可重用模組。
- 各分頁只載入該頁需要的 JSON，避免首頁下載完整可轉債歷史資料。
- 可轉債詳細模式依查詢參數載入資料；未知代碼顯示明確找不到狀態，不回退至任意一檔。
- 興櫃排行與篩選全部從同一份已發布盤後快照衍生，避免摘要與表格數字不一致。
- GitHub Pages 全部使用相對路徑，確保專案子路徑部署正常。

## 更新與失敗處理

- 沿用平日 20:30、21:30、23:00 的盤後更新排程。
- 興櫃盤後資料加入既有斷點續抓與原子發布流程。
- 新候選快照通過完整欄位、日期、唯一性與筆數驗證後，才取代上一版。
- 官方來源無法連線、回傳空資料或格式改變時，保留上一個已驗證版本並顯示其真實資料日。
- 不顯示「即時更新」按鈕，也不讓瀏覽器直接請求官方 OpenAPI。

## 無障礙與視覺要求

- 延續目前的深色／淺色雙主題與非綠色色系。
- 所有文字與背景維持 WCAG AA 對比。
- 表格欄名可由螢幕閱讀器辨識，篩選結果使用 `aria-live` 回報。
- 排行顏色不能作為唯一判斷方式，必須同時顯示正負號與文字。
- 手機主要操作不依賴長距離垂直捲動或水平表格捲動。

## 測試與驗收

- 先以測試定義五個獨立網址、導覽連結與標題，再修改 HTML。
- 驗證 GitHub Pages 子路徑下所有 CSS、JavaScript、JSON 與頁面連結。
- 驗證興櫃來源正規化、無成交、缺值、重複代號、日期與數值單位。
- 驗證排行、漲跌統計、篩選與表格均由相同快照產生。
- 驗證可轉債總表與詳細模式互相切換，不再依賴向下捲動。
- 驗證首頁不載入大型可轉債歷史檔。
- 執行完整建置、型別檢查、程式規範檢查及既有自動化測試。
- 正式部署後，以桌面與手機寬度實際檢查五個分頁及至少一檔可轉債詳細模式。

## 不在本次範圍

- 盤中即時行情。
- 興櫃買價、賣價與逐筆成交。
- 使用參考網站或其他第三方網站作為正式資料來源。
- 投資推薦、預測、評分或買賣訊號。
- 自訂網域審核流程。
