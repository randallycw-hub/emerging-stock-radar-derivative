## 4. 接續工作與驗收順序

1. **更新既有已核准盤後來源。** 建立新候選、核對官方交易日及跨檔一致性；失敗保留原版，不把 9/4 改標新日期。
2. **補 CB 競拍模型。** 先完成 CB 用途與利用範圍核准，再建立獨立完整券碼契約、取消／未開標情境、時程與結果分欄，接到發行表及個券頁。
3. **取得有效申報案件及精確公告。** 驗 XLSX／ODS 簽章、工作表、日期、同公司多案及撤回；分開記公告、送件、生效、訂價、掛牌。
4. **補公司資料與歷史。** 優先相同日期與口徑的公司資料；在有真實歷史後才產生同期比較，不製造缺日數據。
5. **最後做逐頁驗收與發布。** 前台只放有用途的市場欄位，來源 ID、pending、缺漏原因、匯入差異及資料完整度留後台；資料品質與來源核准不因藏起欄位而放寬。

### 欄位與案件盤點

國內 CB 僅取案件類別完全等於「轉換公司債(有擔保)」或「轉換公司債(無擔保)」，共 **111 筆申報案件**：94 筆結案類型為生效、3 筆自行撤回、14 筆結案類型空白。另有 11 筆海外轉換債，排除於本次國內 CB 範圍。111 是案件數，不是 111 個完整券碼，也不等於前台可直接新增 111 檔。

| 官方欄位 | 接入時必須保留的意義 |
| --- | --- |
| 證券代號 | 四碼公司碼，不是完整 CB 代碼 |
| 案件類別／金額／幣別／承銷商 | 用於同公司多案核對；不得只憑公司名稱配券 |
| 收文日期 | 官方收件日，不能宣稱是公司實際送件日 |
| 自動補正日期 | 可能是多日期清單，例如正達的 4/23、5/21、6/1，不能硬解析成單一日期 |
| 停止生效／解除生效日期 | 各自獨立的程序事件，不能誤當完成生效 |
| 生效日期＋結案類型 | 須一起解讀；14 筆未結案都有晚於 9/9 的日期，不能因日期欄有值就判為已生效 |
| 廢止／撤銷、自行撤回、退件日期 | 保留案件終止事件；不列入前台進行中清單，但不刪除內部歷史 |

### 後續接入與驗收邊界

1. 先完成精確附件發現規則、授權紀錄及來源契約核准；不硬編今天檔名當成永久端點，也不自動允許任意下載網域。
2. 嚴格驗格式、大小、表頭、工作表、民國日期與案件類型。HTTP 200 的 HTML 必須拒絕，失敗不替換已驗證快照。
3. 先建立「申報案件」層，保留原始列與內容雜湊供內部追溯；列號只是本版定位，不能當跨日穩定案件 ID。
4. 結案類型、實際／未來日期、補正及撤回各自建模。不得把有未來生效日期的未結案案件顯示為已核准；撤回不混入進行中統計。
5. 精確 CB 對照需核對公司、金額、擔保、承銷、時間與正式公告；未匹配／歧義案件保留在內部待對照，不猜券碼或複製到同公司所有 CB。
6. 同一份已驗證案件資料供發行表、個券頁及事件頁使用；維持前台只呈現必要的資料、來源及日期，不增加來源 ID、缺漏狀態或匯入檢查文字。
7. 競拍資料獨立處理。證期局附件沒有競拍期間、初始轉換價訂價基準日或完整 CB 碼，不能把這份表當成已補齊全部發行流程。
